Sensible.

A reactive UI library in about ten kilobytes. No build step, no virtual DOM, no dependencies — just HTML attributes that do what they look like they do. Every directive is below.

i.

A name, reflected.

Two-way binding with a template expression. s-bind on the input keeps the variable in sync; s-bind on the paragraph (with {name} in its text) renders the value back. s-if hides the line until you've typed something. Add s-blur to update on blur instead of every keystroke.

Pleased to meet you, {name}.

View source 
<input s-bind="name" type="text" placeholder="Type something…">

<p s-if="name.length > 0" s-bind="name" s-cloak>
  Pleased to meet you, {name}.
</p>

ii.

A button that knows when.

Conditional rendering with a compound expression. The submit button stays hidden until both fields have content — no JavaScript, no event listeners, just an attribute that reads like English.

View source 
<input s-bind="fullName" type="text">
<input s-bind="email"    type="email">

<button s-if="fullName.length > 0 && email.length > 0">
  Create record
</button>

iii.

Sums that derive themselves.

Computed values are read-only variables defined as expressions. subtotal depends on price and quantity; tax depends on subtotal; total depends on both. SensibleJS figures out the chain.

Subtotal
${subtotal.toFixed(2)}
Tax (7%)
${tax.toFixed(2)}
Total
${total.toFixed(2)}
View source 
<!-- HTML -->
<input s-bind="price"    type="number">
<input s-bind="quantity" type="number">

<dd s-bind="total">${total.toFixed(2)}</dd>

// Store
data: {
  price:    { type: Number, default: 10 },
  quantity: { type: Number, default: 1 },
  subtotal: { computed: 'price * quantity' },
  tax:      { computed: 'subtotal * 0.07' },
  total:    { computed: 'subtotal + tax' }
}

iv.

A list that listens.

List rendering with s-for and keyed reconciliation via s-key. The search input uses s-debounce to wait until you stop typing before filtering. Click any item to toggle its done state — s-class applies the strikethrough, s-click handles the toggle.

  • {t.done ? '●' : '○'} {t.text}

No matches.

View source 
<!-- HTML -->
<input s-bind="search" s-debounce="150" type="search">

<ul>
  <li s-for="t of filteredTasks" s-key="t.id"
      s-click="t.done = !t.done">
    <span>{t.done ? '●' : '○'}</span>
    <span>{t.text}</span>
  </li>
</ul>

// Store
data: {
  search: { type: String, default: '' },
  tasks:  { type: Array, default: [/* … */] },
  filteredTasks: { computed:
    "tasks.filter(t => t.text.toLowerCase().includes(search.toLowerCase()))"
  }
}

v.

Styles that respond.

Three directives handle styling without touching JavaScript: s-css writes inline styles, s-class toggles class names, s-attr adds or removes attributes. The bar fills as you type, changes color at thresholds, and updates its aria-valuenow for screen readers.

characters typed.

View source 
<!-- HTML -->
<div s-attr="aria-valuenow: bar.length; role: 'progressbar'">
  <div s-css="width: barWidth"
       s-class="warning: barWarning; ready: barReady; full: barFull"></div>
</div>

<p s-if="bar.length > 0">
  <span s-text="bar.length"></span> characters typed.
</p>

// Store — push the logic into computed values
data: {
  bar:        { type: String, default: '' },
  barWidth:   { computed: "bar.length * 3.5 + '%'" },
  barWarning: { computed: "bar.length >= 5 && bar.length < 15" },
  barReady:   { computed: "bar.length >= 15 && bar.length < 30" },
  barFull:    { computed: "bar.length >= 30" }
}

vi.

Events with manners.

A dropdown that handles all the small things: opens on click, closes on outside click via s-unclick, closes on Escape via the s-on keyboard modifier, and animates open/closed with s-transition. s-ref would let you focus a specific element from anywhere.

  • Profile
  • Settings
  • Sign out

Try Esc or click outside · Last choice:

View source 
<div s-unclick="menuOpen = false"
     s-on="keydown.escape: menuOpen = false">

  <button s-click="menuOpen = !menuOpen" s-ref="menuTrigger">
    <span s-text="menuOpen ? 'Close ▴' : 'Open ▾'"></span>
  </button>

  <ul s-if="menuOpen" s-transition="menu">
    <li s-click="(menuOpen = false, lastChoice = 'Profile')">Profile</li>
    <!-- … -->
  </ul>
</div>

/* CSS for the named transition */
.menu-enter, .menu-leave-to { opacity: 0; transform: translateY(-4px); }
.menu-enter-active, .menu-leave-active { transition: all 0.18s ease; }

Also in the box.

Directives and features that didn't get their own demo, but are worth knowing about.

s-html — Raw HTML

Sets innerHTML from an expression. The unsafe sibling of s-text — only use with trusted content.

s-src — Image binding

Binds an img tag's src attribute. Especially useful inside s-for loops over avatar URLs or thumbnail lists.

s-data — Inline state

Define variables right in the markup, no global store needed. Perfect for one-off widgets: <div s-data="{open: false}">

Watchers

Add a watch function to any variable to react to changes. Receives (newValue, oldValue). Good for logging, syncing to APIs, or triggering side effects.

onInit

A lifecycle hook that fires once after the store initializes. Read URL params, fetch initial data, or set up the world before anything renders.

Persistence

Set persist: true on the store and every variable saves to localStorage automatically. State survives refreshes with zero glue code.

When to reach for it.

SensibleJS isn't trying to replace your framework. It's another option in the same neighborhood as Alpine — with one less thing to wire up.

Alpine and Vue are both excellent. SensibleJS answers a slightly different question: what if the library knew about localStorage and didn't make me wire it up myself?
